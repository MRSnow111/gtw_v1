# GTW — дизайн-спецификация v1

Статус: утверждена 2026-11-16. GTW — веб-шлюз к агенту (Hermes). Единица интерфейса — **ход агента (turn)**, а не «сообщение-пузырь».

> **СТАТУС РЕАЛИЗАЦИИ (2026-11-25, волна 3).** Реализовано: лента ходов,
> tool-строки с раскрытием, approvals/clarify-карточки, панель артефактов
> (tab-список + просмотрщики + скачивание + live-браузер), композер с
> авторастом и `/`-командами, сайдбар с поиском по заголовку, инлайн-
> переименованием и удалением чатов, мобильный drawer, состояния (пустой чат,
> ошибки, скелетоны).
>
> Не реализовано:
> - контракт протокола §3 в буквальном виде — фактический protocol плоские
>   WS-кадры адаптера (см. docstring `plugin/adapter.py`), см. пометку в §3;
> - ленивая подгрузка полного tool-вывода **с сервера**: «Показать всё»
>   разворачивает строки, уже пришедшие в кадре (`TurnComponents.tsx`), отдельного
>   запроса `tool.output` нет;
> - `commands.list` от сервера: список slash-команд композера приходит из
>   сид-данных (`seedCommands` в `src/lib/demoData.ts` → `liveStore`/`demoStore`),
>   событиями от gateway не отдаётся;
> - очередь сообщений и счётчик «N сообщений в очереди» из §4 — не реализуется
>   (посланный во время хода текст уходит сразу, индикатор соединения показывается
>   без счётчика очереди);
> - `chat.model` — детерминированный выбор модели из UI есть (пикер + `set_model`),
>   но не в форме исходной спеки;
> - **темы**: светлой/system-темы нет — `src/providers.tsx` фиксирует
>   `defaultTheme="dark"`, `enableSystem={false}`, `forcedTheme="dark"`,
>   переключателя в UI тоже нет; токены `:root` в `app/globals.css` подписаны
>   «Midnight Fern (dark is the only theme for now)», палитра own (primary
>   `#8FB8AE`), shadcn-обёрток в бою не осталось. Отдельная задача — завести
>   вторую тему и вынести токены в один слой;
> - сайдбар: группировка «Сегодня / Yesterday / …» реализована как относительные
>   метки времени (`date-fns`), жёстких секций-заголовков по дням нет.
>
> Вне v1 (§8, зафиксировано и не сделано): мультипользовательские чаты, шеры
> ссылок, голосовой ввод, экспорт чатов, поиск по содержимому сообщений.

## 1. Архитектура экранов

Три колонки:

```
┌──────────┬──────────────────────────┬───────────────┐
│ Сайдбар  │  Лента чата              │ Панель        │
│ чатов    │  (ходы юзера + агента)   │ артефактов    │
│ w-64     │  flex-1, max-w-4xl       │ w-[28rem],    │
│          │                          │ по требованию │
└──────────┴──────────────────────────┴───────────────┘
```

Роуты: `/` (пустой новый чат) и `/chat/[id]`. Префикс `/app` убрать.
Панель артефактов — третья колонка, скрыта по умолчанию, открывается при клике на артефакт/файл, закрается крестиком или `Esc`. На ширине < 1024px панель становится overlay поверх ленты.

## 2. Модель хода агента (главный компонент)

Ход агента — вертикальный блок из секций в порядке появления:

1. **Thinking** — серая строка «Думает…» со спиннером; по завершении схлопывается в `Думал 4.2с` (не показывать детальный reasoning, только факт и длительность).
2. **Tool-вызовы** — компактные строки: иконка инструмента, имя и краткий аргумент (`terminal: npm run build`), статус ⏳/✅/❌/⏱. Клик — раскрытие: аргументы (формatted) + вывод, обрезанный до 30 строк с кнопкой «Показать всё» (полный вывод лениво с сервера). Ошибка инструмента — красная рамка слева, вывод виден сразу без раскрытия.
3. **Текст ответа** — Markdown: код с подсветкой и кнопкой «копировать», таблицы, списки. Стриминг с курсором-палочкой (уже есть).
4. **Блок подтверждения** (approval) — встраивается в поток, пока не решён:
   - рамка жёлтая: «Агент просит разрешения выполнить…», ниже код команды полностью;
   - кнопки **Подтвердить** (primary) / **Отклонить** (ghost) + поле комментария (опционально);
   - после решения блок схлопывается в строку «✅ Разрешено юзером» / «❌ Отклонено» и остаётся в истории;
   - при уходе со страницы незакрытый approval сохраняется; при возврате — снова активен, пока не протух (TTL сервера).
5. **Служебная строка хода** — под блоком, `text-xs text-muted-foreground`: время, токены (in/out), стоимость если есть. В hover — действия: копировать ответ, регенерировать, скопировать markdown.

Ход юзера — правый пузырь (как сейчас), но с Markdown без подсветки, статус-галочкой (⏳/✓/✗) и чипами вложений.

Соседние ходы агента разделяются отступом 24px + тонкий разделитель только при смене статуса генерации.

## 3. Протокол событий (контракт v2)

Добавить к существующему `events.ts`:

```ts
// client → server
| { type: "approval.decide"; chatId: string; requestId: string;
    decision: "allow" | "deny"; comment?: string }
| { type: "chat.history"; chatId: string; before?: string; limit: number }

// server → client
| { type: "approval.request"; chatId: string; requestId: string;
    tool: string; argsPreview: string; fullArgs?: string; expiresAt: string }
| { type: "tool.start";   chatId: string; turnId: string; callId: string; tool: string; argsSummary: string }
| { type: "tool.delta";   chatId: string; callId: string; chunk: string }
| { type: "tool.end";     chatId: string; callId: string; status: "ok" | "error" | "cancelled";
    outputPreview: string; outputBytes: number }
| { type: "tool.output";  chatId: string; callId: string; fullOutput: string }   // ответ на запрос «показать всё»
| { type: "turn.usage";   chatId: string; turnId: string; promptTokens: number;
    completionTokens: number; durationMs: number }
| { type: "chat.title.updated"; chatId: string; title: string }
| { type: "chat.history.page"; chatId: string; messages: Message[]; hasMore: boolean }
```

> Не реализовано: имена событий этого контракта во фронте не используются.
> Фактический protocol — плоские WS-кадры адаптера (`message`/`draft`/
> `message_edit`/`status`/`approval_request`/`clarify_request`/`artifact`/
> `history`/`session_info`/`models`/…), типы — `src/types/events.ts`.

Правила:
- `turnId` группирует всё внутри одного хода; `callId` — один tool-вызов.
- Ключ ре-отправки: `clientMessageId` идемпотентен, сервер дедуплицирует.
- `chat.delta.fullText` в `chat.done` — источник истины: при расхождении с накопленными дельтами стор перебивает полным текстом.
- История: REST не нужен, всё тем же сокетом (`chat.history`), пагинация backwards по `before`.

## 4. Composer

- Автораст textarea (1 → 8 строк, дальше скролл внутри).
- Enter — отправить, Shift+Enter — перенос (как есть).
- Ввод `/` в начале строки — дропдаун команд (`/stop`, `/new` и т.д.), навигация стрелками, Tab/Enter — выбрать. Список команд приходит от сервера событием `commands.list` при подключении (не хардкод).
- Кнопка Stop активна весь ход (не только при генерации текста — tool-вызов тоже отменяется через `chat.cancel`).
- Файлы: кнопка + drag&drop на всю ленту (подсветка рамки зоны). До отправки — чипи над textarea: иконка типа, имя, размер, крестик; прогресс загрузки; `failed` — красный с retry.
- Индикатор соединения — не иконка-wifi в шапке (убрать тестовый переключатель), а плашка над композером при `status !== connected`: «Соединение потеряно. Переподключение…» + «N сообщений в очереди».

## 5. Сайдбар

- Кнопка «Новый чат» (как есть) + поле поиска под ней (фильтр по заголовку, локально).
- Элемент списка: заголовок (1 строка, ellipsis), превью последнего сообщения (`text-xs`, 1 строка), относительное время справа; hover — кнопка «⋯» (переименовать inline / удалить с подтверждением).
- Активный чат во время генерации — спиннер вместо времени.
- Группировка: Сегодня / Yesterday / На этой неделе / Ранее. Порядок — по `updatedAt`; `chat.title.updated` поднимает чат и обновляет заголовок без клика.
- Низ: «Настройки» (модалка: тема, имя юзера, WS URL) и переключатель темы (иконка солнце/луна, system по умолчанию, localStorage).
- Мобильный (<768px): сайдбар — overlay-drawer поверх чата, кнопка-гамбургер в шапке ленты.

## 6. Панель артефактов (v1 — да)

- Источник артефактов: файлы из tool-выводов (`file.ready`, пути в выводах инструментов) и вложения юзера.
- Табы-список слева в панели (если артефактов >5, с поиском), контент справа:
  - код/текст — просмотрщик с подсветкой, кнопка «копировать», номер строки;
  - изображение — вписано по ширине, клик — fullsize;
  - прочее — карточка с метаданными и кнопкой скачать.
- Открытие артефакта подсвечивает source-строку tool-вызова в ленте (короткая анимация).
- Состояние загрузки — скелетон; ошибка загрузки — retry.

## 7. Темы, типографика, состояния

- `next-themes`: system светлая/тёмная + ручная, класс `.dark` (CSS-переменные уже есть).
  **Не реализовано:** включён только тёмный (`enableSystem={false}`,
  `forcedTheme="dark"` в `src/providers.tsx`), переключателя темы в UI нет.
- Primary оставить shadcn-синим до появления бренд-гайдов; зафиксировать токены в одном месте — `globals.css`.
  **Частично:** токены зафиксированы в `app/globals.css` (`:root`), но primary уже
  не shadcn-синий, а собственная палитра «Midnight Fern» (`#8FB8AE`).
- Шрифт системный (как в README).
- Обязательные состояния: пустой чат (подсказки-карточки с примерами запросов), загрузка истории (6 скелетонов), `error` события (красная строка в потоке + retry), несуществующий `/chat/[id]` («Чат не найден» + кнопка «На главную»), пустой сайдбар («Пока нет чатов»).

## 8. Вне v1 (зафиксировано, не делаем)

- Мультипользовательские чаты, шеры ссылок на чат.
- Голосовой ввод, экспорт чатов, поиск по содержимому сообщений (в v1 только по заголовкам).
- Детерминированный выбор модели из UI (`chat.model` в типе есть, UI позже).
